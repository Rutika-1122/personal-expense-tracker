    LocalStorage to Database Migration Architecture

    How this client-side prototype can scale into a full-stack enterprise application.

    1. Storage Comparison

    • Current (localStorage): Synchronous, limited to ~5MB, scoped to single browser/device, no multi-user capability.
    • Database (SQL/NoSQL): Persistent, dynamic queries, scalable, multi-user authentication, server-side encryption.

    2. Database Schema Design (SQL)

    CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    email VARCHAR(255) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE categories (
    id SERIAL PRIMARY KEY,
    name VARCHAR(50) NOT NULL,
    icon VARCHAR(10)
);

CREATE TABLE expenses (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID REFERENCES users(id) ON DELETE CASCADE,
    category_id INT REFERENCES categories(id),
    amount DECIMAL(10, 2) NOT NULL,
    description TEXT,
    expense_date DATE NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

    3. Backend REST API Routes

    • POST /api/v1/auth/register - Register user
    • POST /api/v1/auth/login - JWT authentication
    • GET /api/v1/expenses - Fetch user expenses with query filters
    • POST /api/v1/expenses - Create expense record
    • PUT /api/v1/expenses/:id - Update existing expense
    • DELETE /api/v1/expenses/:id - Remove expense
